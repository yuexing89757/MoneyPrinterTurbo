# 批量关键词视频生成设计

## 背景与目标

MoneyPrinterTurbo 已具备从单个主题生成文案、搜索或生成素材、合成配音与字幕并输出视频的完整流水线，也具备 WebUI 后台队列、运行期任务状态和磁盘任务历史。本功能在这些能力之上增加持久化的批量工作流。

用户在批量页面中每行输入一个关键词。系统为每个关键词独立生成一篇约 800 个中文字的旁白文案，内容依次说明关键词的出处、含义和对现实生活的启发，然后无需人工审核，自动生成一个视频。页面展示批次与任务状态、文案摘要、成片预览和下载入口；浏览器刷新或应用重启后，历史记录仍可查看。

## 成功标准

- 单批可提交 1 至 100 个非空关键词，每行一个。
- 每个输入行都是独立任务；重复关键词不会被合并或去重。
- 每个任务使用同一批次提交时的视频配置快照，自动执行“文案 → 配音与字幕 → 素材 → 成片”。
- 文案目标长度为 700 至 900 个中文字，适合作为连续旁白，不输出 Markdown 标题或提示语。
- 文案覆盖出处、含义和现实启发；没有可靠出处时明确说明，不虚构典故、人物或年代。
- 单个任务失败不阻断批次中的后续任务。
- 批次和任务关联关系持久化；刷新或重启后可恢复历史列表与已完成视频的下载。
- 应用重启时未完成且无法继续执行的任务标记为“已中断”，用户可单项重试。

## 非目标

- 本次不增加多任务并发控制界面，WebUI 继续按现有策略一次执行一个视频任务。
- 本次不实现进程重启后的断点续跑；中断任务通过显式重试创建新尝试。
- 本次不增加独立前端框架或新的公共批处理 HTTP API。
- 本次不提供逐篇文案人工审核步骤。
- 本次不改变现有单视频页面、CLI 批处理清单或视频生成核心算法。

## 用户流程

1. 用户从 WebUI 顶部切换到“批量生成”。
2. 用户在多行输入框中每行输入一个关键词，并设置本批次共用的视频、素材、配音和字幕选项。
3. 页面实时显示有效关键词数量。空行被忽略，重复行保留。
4. 用户点击“开始批量生成”。系统先验证整批输入、外部服务凭据、素材来源、上传文件和需要明确确认的付费服务。
5. 验证全部通过后，系统创建批次和独立任务，将任务按输入顺序加入现有 WebUI 队列。
6. 页面立即显示任务表并轮询状态。关闭或刷新页面不影响后台任务。
7. 已完成任务可在线播放并下载；失败或中断任务可单项重试。
8. 用户可在“当前批次”和“历史批次”间切换，并按全部、进行中、完成、失败或中断筛选。

## 架构

### 页面层

在现有 Streamlit 应用内增加“单个生成 / 批量生成”导航，并把批量页面实现为独立模块，避免继续扩大 `webui/Main.py` 的职责。批量页面复用现有视频、音频、字幕和素材设置组件或由这些组件提取出的共享 helper。

批量页面负责输入、校验提示、批次列表和任务操作，不直接执行视频流水线。提交和轮询均通过服务层完成。

### 批次服务

新增批次服务，职责限定为：

- 解析并校验关键词行。
- 创建批次、任务条目和尝试记录。
- 将批次 JSON 原子写入磁盘。
- 查询、筛选和协调批次状态。
- 根据运行期任务状态和任务目录恢复展示状态。
- 为失败或中断条目创建新的重试任务。

批次服务不生成文案、不处理媒体，也不依赖 Streamlit 会话状态。

### 任务调度

每个关键词构造一个独立 `VideoParams` 深拷贝，设置：

- `video_subject` 为当前关键词。
- `video_script` 为空，使现有流水线调用 LLM。
- `video_script_prompt` 追加批量知识解读文案约束。
- 其余字段来自批次提交时的共用配置快照。

任务继续通过 `app.services.webui_task.submit_generation()` 进入现有有界队列，并最终调用 `app.services.task.start()`。这样可以复用当前的配置锁、日志捕获、错误终态、任务目录和所有音视频产物。

批量提交前应在任务管理器锁内预留或验证足够队列容量，确保整批提交不会因队列中途满载而只入队一部分。若启动第一个工作线程后出现无法预见的调度错误，批次服务必须把尚未入队的条目标为失败，并保留已经提交的条目，不能留下永久“等待中”状态。

### 文案提示词

新增专用的批量知识解读提示词构造函数，并通过现有 `video_script_prompt` 传入，不替换用户选择的模型或全局系统提示词。提示词要求：

- 以当前关键词为唯一主题。
- 使用自然、准确、适合中文视频旁白的连续文本。
- 总长度以 800 个中文字为目标，接受 700 至 900 字。
- 内容逻辑依次覆盖出处或形成背景、核心含义、现实生活启发。
- 不输出 Markdown、章节标题、字数声明或模型说明。
- 不确定或不存在公认出处时明确说明，禁止杜撰可核验事实。
- 现代术语、网络用语或外来词可以说明传播背景与常见用法，不能强行附会古代典故。

LLM 输出长度具有概率性，700 至 900 字是提示目标而不是对生成文本进行机械截断。机械截断可能破坏句子和旁白完整性，因此首版仅保存实际字数并在偏离目标时记录非阻断警告。

## 持久化模型

批次文件位于：

`storage/batches/<batch-id>.json`

每次写入先写同目录临时文件，刷新并关闭后使用原子替换发布。批次文件只保存元数据和关联关系，不复制文案、音频、素材或视频。

建议结构：

```json
{
  "schema_version": 1,
  "batch_id": "uuid",
  "created_at": "ISO-8601",
  "updated_at": "ISO-8601",
  "settings_summary": {
    "video_source": "pexels",
    "video_aspect": "9:16",
    "voice_name": "zh-CN-XiaoxiaoNeural-Female",
    "video_count": 1
  },
  "params_snapshot": {
    "video_aspect": "9:16",
    "video_source": "pexels",
    "voice_name": "zh-CN-XiaoxiaoNeural-Female"
  },
  "items": [
    {
      "item_id": "uuid",
      "position": 1,
      "keyword": "关键词",
      "attempts": [
        {
          "task_id": "uuid",
          "created_at": "ISO-8601",
          "process_owner": "per-process-uuid"
        }
      ]
    }
  ]
}
```

完整任务产物参数继续由现有任务目录中的 `script.json` 保存。批次文件另外保存一份 `VideoParams` 的无密钥快照，确保任务即使在 `script.json` 产生前失败，重启后仍能按原配置重试。`VideoParams` 本身不包含 API Key；写入前仍按字段白名单序列化，并排除不可恢复的临时上传路径。批次文件不写入 API Key、令牌、上传文件内容或外部服务凭据。`settings_summary` 只用于低成本列表展示，`params_snapshot` 用于重试。

上传配音会在首次提交时复制到每个目标任务目录。重试时只能从上一次仍存在且通过任务目录白名单校验的副本复制；找不到副本时要求用户重新上传。共享本地素材仍使用现有 `storage/local_videos` 白名单路径。

每个条目的当前尝试是 `attempts` 中最后一项。重试追加尝试，不删除或覆盖旧任务目录。

## 状态与恢复

页面展示状态由批次条目、当前尝试的运行期状态和磁盘产物合并得出：

- `waiting`：批次已保存，任务已进入队列但尚未开始流水线。
- `script`：进度 5% 至 19%，正在生成文案或搜索词。
- `audio`：进度 20% 至 39%，正在生成配音或字幕。
- `materials`：进度 40% 至 49%，正在获取或生成素材。
- `video`：进度 50% 至 99%，正在合成成片。
- `complete`：状态为完成且至少存在一个白名单内的最终视频。
- `failed`：任务状态明确记录失败及失败阶段。
- `interrupted`：应用启动后没有对应活动工作线程，磁盘中没有成片，而最后记录仍是等待或处理中。

当前流水线已在关键阶段更新固定进度，并在失败时保存 `failed_stage`，首版直接基于这些信息映射展示阶段，不为状态展示侵入式修改核心媒体函数。

每次应用启动会生成一个进程所有者 UUID，并随尝试写入批次文件。恢复逻辑只有在尝试所有者与当前进程一致且现有状态仍为处理中时，才把它视为活动任务。重启后的所有者不同；没有最终成片的旧等待/处理中任务展示为“已中断”，不会自动重新调用可能产生费用的外部服务。

批次 JSON 无法解析或结构不合法时，该文件不参与普通列表渲染，并在页面的恢复警告区显示文件名和错误摘要。服务不得因一个损坏文件阻止其他批次加载。

## 页面设计

### 输入与设置

- 多行关键词输入框，每行一项。
- 有效任务数量提示和输入错误提示。
- 复用现有四组设置：文案、视频、音频、字幕。
- 同一批次共享一份提交时的参数快照；提交后的 UI 改动不影响已排队任务。
- 单个批次最多 100 项；单个关键词去除首尾空白后不得为空，并使用与现有主题输入一致的安全长度上限。

### 任务表

任务表按输入顺序展示：

- 序号
- 关键词
- 状态
- 总进度
- 文案摘要与实际字数
- 更新时间
- 操作

完成任务显示视频播放器和下载按钮。下载名沿用现有安全文件名逻辑，以关键词命名；若一个任务产生多个视频，则追加序号。

失败和中断任务显示“重试”。重试只作用于单个条目，使用批次原配置；如果原配置依赖无法恢复的上传音频或本地素材，页面要求用户重新提供文件或更改配置，不能静默切换来源。

### 历史与筛选

- 默认定位最近创建的批次。
- 支持选择当前或历史批次。
- 支持全部、进行中、完成、失败和中断筛选。
- 页面使用 Streamlit Fragment 定时轮询，不阻塞主页面交互。
- 批次文件只在成员关系或尝试历史变化时写入；频繁的进度刷新从现有任务状态读取，避免每 0.5 秒写磁盘。

## 校验与错误处理

提交前执行整批预检：

- 关键词数量和长度。
- 视频来源是否合法及所需 API Key 是否存在。
- LLM 文案服务配置是否完整。
- 付费视频或音乐服务是否已明确确认。
- 本地素材、上传配音和上传背景音乐是否可用。
- FFmpeg 是否可用。
- 队列是否能容纳整个批次。

任何可预见的预检失败都会整批拒绝，不创建批次或调用外部服务。单个任务运行时失败只更新该任务，队列继续执行后续条目。

下载和预览前必须把最终路径解析到 `storage/tasks` 白名单目录内并确认文件存在。页面不得把服务器任意绝对路径作为可下载内容。

## 测试策略

实现遵循测试驱动开发。新增测试至少覆盖：

1. 关键词解析：空行、空白、重复项、顺序、1 至 100 条边界和超限拒绝。
2. 文案提示：包含目标字数、出处、含义、现实启发与禁止虚构规则，并保留用户自定义风格约束。
3. 批次存储：创建、原子更新、读取、schema 校验、损坏文件隔离和无敏感字段。
4. 调度：每项获得唯一任务 ID、参数深拷贝、按输入顺序提交、整批容量预检和中途异常终态。
5. 故障隔离：一个任务失败后后续任务仍被执行。
6. 状态映射：等待、各处理阶段、完成、失败和重启中断。
7. 恢复：完成任务从任务目录恢复视频；旧处理中任务变为中断；重试追加尝试且保留旧任务。
8. 页面：批次筛选、状态过滤、文案摘要、视频预览、下载名和重试按钮。
9. 安全：下载路径白名单、无 API Key 持久化、损坏 JSON 不影响其他批次。
10. 回归：现有 WebUI 后台任务、任务历史、LLM、CLI 和核心视频流水线测试继续通过。

## 兼容性与迁移

批次功能只新增 `storage/batches`，不修改既有 `storage/tasks` 的目录格式。旧任务仍由现有任务管理器显示，但不会被自动归入历史批次。批次文件包含 `schema_version`，未来字段演进时可以显式迁移或拒绝不支持的版本。

当 Redis 状态开启时，运行期状态继续通过现有 `state` 抽象读取；批次成员关系仍以本地批次文件为准，与当前任务产物落盘方式一致。

## 验收场景

1. 输入三个不同关键词并提交，页面立即出现三个等待任务，随后按顺序完成，每项产生独立文案和视频下载。
2. 输入两个相同关键词，系统保留两个独立任务和两个任务目录。
3. 第二个任务因外部素材服务失败，第三个任务仍继续生成；第二项展示失败原因并可重试。
4. 完成一部分任务后重启应用，已完成项仍可下载，原等待或处理中项显示中断。
5. 重试中断项后，批次中保留旧尝试记录，新任务成功后下载指向新成片。
6. 输入超过 100 条、缺少必要 API Key 或队列容量不足时，页面整批拒绝且不产生外部调用。
